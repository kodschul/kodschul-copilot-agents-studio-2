# Lab 7.10: The Nextise Agentic Way – Showcase & Abschluss

Zum Abschluss steht nicht ein einzelner Prompt, sondern eine ganze Baukette im Fokus. Dieses Lab verdichtet die zwei Kurstage auf ein übertragbares Muster für fachliche und technische KI-Arbeit.

**Leitfragen:**

<details>
<summary>Was ändert sich, wenn KI genutzt wird, um KI zu bauen?</summary>

Die Arbeit verschiebt sich von einer Einzeleingabe zu einer Kette aus Problemklärung, Spezialisierung, Test und Governance. Qualität entsteht stärker durch den Prozess als durch einen einzelnen Prompt.

</details>

<details>
<summary>Welcher Schritt der Kette bringt den größten Hebel?</summary>

Das hängt vom eigenen Kontext ab. Häufig liegen die größten Hebel in einer sauber gewählten Harness-Entscheidung und in kleinen, gut getesteten Skills.

</details>

<details>
<summary>Warum ist dieses Muster auch für Coding-Arbeit relevant?</summary>

Weil dieselbe Logik gilt: Problem schärfen, Spezialisten einsetzen, kleine wiederverwendbare Bausteine bauen, Ergebnisse evaluieren und Governance nicht ans Ende schieben.

</details>

- Die Nextise Agentic Way ist eine Kette aus Problemklärung, Architektur, Skill-Bau, Agent-Orchestrierung, Tool-Nutzung und Review.
- Dasselbe Muster lässt sich auf Support-, Fach- und Coding-Szenarien übertragen.

## Die Kette im Überblick

| Schritt | Artefakt | Wozu er dient |
| --- | --- | --- |
| Problem | Use-Case-Canvas mit Assistent 1 | Problem vor Lösung schärfen |
| Struktur | Kurzkonzept mit Assistent 2 | Skills, Ablauf und Grenzen festlegen |
| Skill-Bau | Assistent 3 + `SKILL.md` | wiederverwendbare Teilaufgaben erzeugen |
| Studio-Agent | GitHub-Copilot-Harness-Agent | Skills, Knowledge, Tools und Delegation bündeln |
| Handlung | Workflow, MCP, Connected Agent | externe Aktion oder Spezialwissen anbinden |
| Qualität | Preview, Evaluate, Monitor, Governance | Wirkung prüfen und Betrieb absichern |

## Demo-Rückblick als Ablaufbild

| Von | Nach | Sichtbarer Übergang |
| --- | --- | --- |
| Problem | Assistants 1–3 | aus Idee wird eine testbare Spezifikation |
| Spezifikation | Skill | aus Text wird ein wiederverwendbarer Baustein |
| Skill | Studio-Agent | aus Bausteinen wird ein orchestrierter Agent |
| Agent | Workflow / MCP / Connected Agent | aus Antwort wird Handlung oder Delegation |
| Laufzeit | Evaluate / Monitor | aus Demo wird messbare Qualität und Betriebssicht |

> **Merksatz:** Agentische Qualität entsteht aus einer guten Kette, nicht aus einem magischen Einzelschritt.

## Optionale Entwicklerperspektive

Die Copilot-Studio-Erweiterung für VS Code beschreibt laut Learn den YAML-basierten Arbeitsweg für Agenten und Flows des Standard-Harness. Für den GitHub-Copilot-Harness gilt deshalb: Verfügbarkeit vor Kursbeginn verifizieren, im Kurs sonst nur als Ausblick erwähnen.

## Transfergedanke

Dasselbe Muster passt auch auf Coding-Arbeit: Problem strukturieren, Spezialisten einsetzen, kleine wiederverwendbare Bausteine bauen, Ergebnisse evaluieren und Governance nicht ans Ende schieben.

## Was Sie mitnehmen

- ein klares Muster von der Idee bis zum überprüfbaren Agenten,
- drei Arten von Bausteinen: Skills, Tools/Workflows, Delegation,
- eine einfache Qualitätslogik: Preview, Evaluate, Monitor,
- die Einsicht, dass Governance und Credits von Anfang an zum Design gehören.

## Grenzen

- Die Showcase-Demo ist ein verdichtetes Gesamtbild, kein zusätzlicher Funktionsumfang.
- Die optionale VS-Code-Perspektive bleibt ein Ausblick, solange die Verfügbarkeit für den GitHub-Copilot-Harness nicht bestätigt ist.
- Der größte Hebel ist organisationsabhängig; deshalb endet das Modul mit einem persönlichen Aktionsplan.

## Fazit

- Die Nextise Agentic Way verbindet Problemarbeit, Bausteinbau, Integration und Review.
- Kleine, überprüfbare Schritte sind robuster als ein großer One-Shot-Agent.
- Der Transfer in andere KI- und Coding-Szenarien ist direkt möglich.

Die Übung übersetzt die Showcase-Kette in einen persönlichen ersten Pilotplan.
